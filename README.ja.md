# 熱舞 Online · 個人成績表と成長の記録

> **初めて使う方へ：** わかりやすい [ユーザーガイド](docs/USER_GUIDE.md)をご覧ください。インストール、ゲームフォルダーの設定、成績の見方、よくある質問を順を追って説明しています。

## 最も簡単な使い方：DanceScore.exe（OCR 不要・Python のインストール不要）

1. [Releases ダウンロードページ](https://github.com/ThomasChung0708/dance-score-system/releases/latest)から `DanceScore.exe` をダウンロードし、**専用の空フォルダー**（例：`D:\DanceScore`）に入れてダブルクリックします。初回に「Windows によって PC が保護されました」と表示された場合は、「詳細情報」→「実行」を押してください（exe にはデジタル署名がありません）。ローカルの Web ページが開きます。黒いウィンドウは開いたままにしてください。
2. 右上の「遊戲資料夾」（ゲームフォルダー）を押し、`dance.exe` があるフォルダーのパスを貼り付けて、「儲存並同步」（保存して同期）を押します。
3. 「角色」（キャラクター）のドロップダウンで自分のキャラクターを選びます。
4. いつもどおりプレイします。1 曲終わるたびに成績が自動保存され、公式曲と外部曲（StepMania／osu フォルダーを含みます）の曲リストもゲームと同期されます。

- 成績は exe の隣にある `data` フォルダーに保存されます。バックアップを取り、他の人には共有しないでください。更新時は exe だけを入れ替え、`data` は残してください。
- `results.jsonl` に成績を記録するゲームバージョンが必要です。仕組み、読み取るファイル、形式については [ゲームフォルダーモード](docs/GAME_RESULTS.md)をご覧ください。
- exe に OCR は含まれていません。開発者の方や OCR を予備の手段として使いたい場合は、ソースコードから実行できます。Python 3.10 以上をインストールしてから `LibraryGUI.cmd` をダブルクリックしてください（データはソースコードのディレクトリ内の `data` にあり、exe とは別のデータベースです。exe に切り替える場合は `data` を exe の隣にコピーしてください）。自分で exe をビルドする場合は、Python 3.11 を使って `BuildExe.cmd` をダブルクリックします。成果物は `dist\` に出力されます。
- 以下の OCR 監視と手動操作の手順も引き続き利用でき、ソースコードから実行する場合に使えます。

正常終了し、判定、曲の識別情報、本人の成績行を確認できた場合は、次のように計算します。

- `judged_total = Perfect + Cool + Bad + Miss`
- `EX Score = Perfect × 2 + Cool`
- **本システム独自の MAX = judged_total × 2** です。ゲーム公式の標準 MAX の定義とは異なります。
- 差が 0～150 の場合は MAX -差分、それより大きい場合はパーセント（小数点以下 2 桁）を表示します。

CSV／GameDifficulty のノーツ数は譜面の参考情報として保持し、リザルトの合計では上書きしません。CSV との差異は通知のみに使い、正常終了時に独立した MAX の根拠や 4 項目の差異に関する例外の記入を求めることはありません。GAME OVER の部分的な判定から完全な MAX は設定しません。他に信頼できる完全な算出根拠がない場合は NULL を維持します。

## 操作と保護

[LibraryGUI.cmd](LibraryGUI.cmd) または [MonitorGUI.cmd](MonitorGUI.cmd) を実行し、確認待ちの成績を開きます。曲／難易度、本人の成績行、判定を照合し、確認内容を別途保存してから正式に保存します。不明な値、元画像、生の OCR データ、手動修正の記録を保持します。

MANUAL／VERIFIED_AUTO は引き続き利用できます。信頼できる新しいリザルトは自動保存でき、信頼度が低い場合、項目が欠けている場合、識別情報／本人／Session が信頼できない場合、プレイ間で判定合計が矛盾する場合は、すべて確認待ちになります。**CSV との差異に関する新しい自動処理ルールは、まだ実プレイでの受け入れ検証が必要なため、このバージョンではこうした結果を手動で送信します。** モードを有効にする前の古い確認待ちデータは自動送信しません。

同じ Song ID＋難易度に異なる judged_total がある場合、各記録独自の MAX を保存しますが、その記録のランプは PENDING とし、自動送信とベスト更新を停止します。差分／パーセントによるランキングも一時停止します。EX の方式が既知で、識別情報、本人の行、計算式の根拠が信頼できる場合は EX を比較できます。MAX の定義は別々に扱います。未分類の過去データは、異なる方式の間で自動比較しません。NEW SCORE／NEW LAMP と既存のアニメーションは、送信に成功し、比較可能な場合にだけ実行されます。

Schema8→9 では送信時の検証とベスト記録のクエリだけを変更し、先にバックアップを取ってテーブルごとに照合します。**過去の成績の再計算、Song ID の変更、曲ライブラリの再構築は行いません。** 317 件のテスト、元の PNG による OCR リプレイ、隔離環境の GUI、変更ファイル、ソースの保存、制限については [Phase5C.2 の詳細説明](docs/PHASE5C2_CUSTOM_MAX.md)をご覧ください。テスト成果物は `reports/phase5c2/` にあります。

以下は既存の OCR、曲ライブラリ、起動機能の説明です。過去のフェーズレポートにある古い MAX ルールについては、上記の Phase5C.2 を優先してください。

## リザルト OCR と確認待ちの成績

`MonitorGUI.cmd`／`LibraryGUI.cmd` を起動し、「待確認成績」（確認待ちの成績）をクリックします。既存のリザルトには「辨識此結算」（このリザルトを認識）を使えます。新版のリアルタイム監視では、その回の認識データを再利用して確認待ち項目を作成します。本人のデータ行、P／C／B／M、Combo、元のスコア、評価、正常終了／GAME OVER に対応しています。数値の修正、独立した Song ID の選択、下書きや手動確認内容の保存ができ、再起動後も保持されます。空欄を 0 で補完することはありません。マルチプレイ画面下部の曲の LV は、本人が選んだ譜面と照合する必要があり、HOST の別難易度の値を流用しません。

マルチプレイで Pack がない場合は、標準で全 Custom Pack（connect を含みます）を検索します。独立した Song ID、Pack、SongFolder、ソースファイルをページごとに確認でき、最初の曲を自動選択することはありません。確認待ちページには「重新掃描 SONG 並更新候選」（SONG を再スキャンして候補を更新）を追加しました。バックグラウンドの差分スキャンを再利用し、すべての Pack を対象にします。ソースが未完成の SongFolder は更新を後回しにします。本人の成績行の手動選択、曲の長さの照合、確認根拠の保存に対応しています。曲の入手方法が不明な場合、Pack 名から推定しません。操作、テスト、制限については [マルチプレイの補足説明](docs/PHASE4C_MULTIPLAYER.md)をご覧ください。

共通の EX Score、MAX との差分／パーセント、ACP／AC／CLEAR／FAILED のコア処理を提供します。先に手動確認内容を保存し、次に「確認並儲存成績」（確認して成績を保存）を押して全体の概要を照合し、正式に送信します。新たな送信のたびに事前バックアップを取り、単一トランザクションで保存します。Session／Review の一意制約で重複を防ぎます。正常終了時は完全なノーツ数の照合が必要です。FAILED は部分的な成績を保存でき、不明な MAX は NULL を維持します。履歴ページでは検索、元の証拠、各難易度の最高 EX／ベストランプ、更新通知を確認できます。[Phase 5A の操作と設計](docs/PHASE5A_SUBMISSIONS.md)をご覧ください。

Pack 一覧の色からは、現時点では CANDIDATE しか生成できず、Hover を除外できません。一覧を閉じた後に Pack を個別に手動確認でき、一覧を再び開くと以前の確認は取り消されます。テスト結果、変更ファイル、追加撮影が必要な 4 枚の比較画像については [Phase 4C の説明](docs/PHASE4C_RESULTS.md)をご覧ください。

`OCRStatic.cmd` をダブルクリックすると、`tests/專案測試圖片/` 内のすべての PNG を認識し、`reports/phase4a/results.json` と読みやすいレポートを出力します。実際の元画像 22 枚でテスト済みです。JOINT の 2 つのバージョンは異なる数値を認識できますが、検証済みのデータベースの難易度／時間がない場合は手動確認待ちとし、自動で関連付けません。インストール、起動、精度の定義、制限の詳細は [Phase 4A の説明](docs/PHASE4A_OCR.md)をご覧ください。静止画像用の起動手段は単独で動作し、リアルタイムキャプチャは開始しません。

## GUI

**`LibraryGUI.cmd`** をダブルクリックすると、ローカルの曲ライブラリが開きます。起動ウィンドウは開いたままにし、サービスを終了する場合は **Ctrl+C** を押してください。URL は `http://127.0.0.1:自動選擇的連接埠/`（自動選択されたポート） です。ローカルでのみサービスを提供し、パッケージのインストールは不要です。次のコマンドでも実行できます。

```powershell
python -m dance_results.gui
```

`--database 路徑`（パス） で既存のデータベースを指定でき、`--no-browser` でブラウザーを自動起動しないようにし、`--port 8765` でローカルポートを指定できます。まだデータベースを作成していない場合は、先に `Start.cmd` でインポートしてください。

- 左側で Pack を選択します。現在の選択項目は紫色で表示されます。公式カテゴリにはインポート済みの K モードの曲リストだけを表示し、自作ソースから自動推定しません。connect は「多人下載」（マルチプレイのダウンロード）に独立して表示されます。
- 中央では中国語、日本語、英語の曲名に加え、Pack、フォルダー、保持しているソース名も検索できます。名前の昇順・降順に対応し、1 ページ 60 曲です。同名曲は Song ID、Pack、フォルダーごとに分けて表示します。
- 右側では Artist、ソース形式、元のパス、名前の差異、文字コードの確認待ち情報を確認できます。「原始來源資訊」（元のソース情報）を展開すると、各ソースの Title／Subtitle／Artist／文字コードと候補を確認でき、DWI ではソースの BPM の基本となる元の値も表示します。
- 編集前に **Song ID と SongFolder** を照合し、「確認此難度存在」（この難易度が存在することを確認）にチェックを入れ、EASY／NORMAL／HARD の LV と総ノーツ数を入力して、その難易度の保存ボタンを押します。不明な項目は空欄にでき、保存済みの項目も空欄にして再保存すると NULL にできます。このバージョンでは作成済み難易度の削除はできません。
- 保存のたびに曲の ID、ルートディレクトリ、相対パス、バージョン token を照合します。別のウィンドウで変更されていた場合は再読み込みを求め、上書きや同名曲への誤書き込みを防ぎます。手動入力の数値には `manual` を付け、OCR として扱いません。
- 「更新歌曲庫」（曲ライブラリを更新）は既存の差分スキャンをバックグラウンドで実行し、新規追加された曲／ソース、更新された曲／ソース、警告の件数を表示します。実行中も閲覧できますが、難易度の書き込みは一時停止します。終了後に一覧を自動更新します。ソースがなくなった場合は印を付けるだけで、履歴は削除しません。

古いデータベースはバージョンごとに安全に移行します。schema 4→5 では、先に `data/backups/*.pre-v5.*.sqlite3` のバックアップを作成して検証します。公式データの初回インポート前には pre-official-import バックアップも作成します。既存の ID、名前、パス、スキャンのスナップショット、履歴はテーブルごとに照合して保持します。

## 公式 K モード曲のインポート

> Web ページの「匯入官方 CSV」（公式 CSV をインポート）ボタンは削除しました。ゲームフォルダーを設定すると、公式曲はゲームの `song_table.csv` に合わせて自動更新されます（[ゲームフォルダーモード](docs/GAME_RESULTS.md)をご覧ください）。以下のコマンドラインによるインポートも引き続き利用できます。

従来の手動インポートでは、K の件数、除外件数、新規追加する曲／難易度、ソースの競合をプレビューしてから正式にインポートします。同じデータを再インポートしても追加件数は 0 です。ソースの内容や保存済み難易度が異なる場合は処理全体を停止し、既存データを上書きしません。

CLI だけでも使用でき、OCR、時間の項目、自作曲のスキャン、GUI は不要です。

```powershell
# 読み取り専用のプレビューです。migration は実行しません
python -m dance_results.official_import --csv '.\song_table.csv'

# 先にバックアップし、安全な migration とトランザクションによるインポートを実行します
python -m dance_results.official_import --csv '.\song_table.csv' --import
```

`--database 路徑`（パス） で独立したデータベースを指定でき、`--result 路徑.json`（パス.json） で照合結果を保存できます。GUI の「更新歌曲庫」（曲ライブラリを更新）は引き続き自作／connect フォルダーだけを更新し、公式ソースが消失したとは扱いません。

**mode=K** の Song だけを作成します。T／空欄は除外し、元の CSV は変更しません。公式の識別には catalog＋mode＋fileId＋gn を使い、元の fileId を保持します。同名でも、同じ fileId で gn が異なる場合でも統合しません。ソースは独立した official_song_sources に保存し、既存の 2,930 件のファイルソース ID は変更せず、架空の Pack／SongFolder も追加しません。

公式曲の詳細には fileId、Title、Artist、BPM の元の値と、E／N／H のゲーム内 LV、完全なノーツ数、MAX=ノーツ数×2 を表示します。LV／ノーツ数がともに 0 または空欄の場合は難易度を作成しません。片方だけ値がない場合や不正な数値がある場合は、インポート全体を拒否します。公式曲のカードは現時点ではソース表示用で、自作曲は引き続き手動編集できます。CSV の時間の項目はまだゲーム時間としてインポートしておらず、後続の Phase 4 の仕様を妨げるものではありません。

全手順、識別方法、制限については [公式インポートの説明](docs/OFFICIAL_IMPORT.md)をご覧ください。

## スキャンと旧版のオフラインレポート

1. このディレクトリの **`Start.cmd`** をダブルクリックし、曲ライブラリをスキャン／更新します。
2. SONG のルートディレクトリを選びます。既定値は `D:\Dance v1.9.0-dev-be622\DATA\ADDON\SONG` です。
3. 完了後、`data/library.sqlite3` に自動保存し、既定のブラウザーでレポートを開こうとします。自動で開かない場合は、コマンドウィンドウに表示されたパスから `report.html` を開いてください。
4. レポートは曲フォルダーごとに 1 行で表示します。曲名、フォルダー、ソースファイル名で検索でき、保存グループ／曲名の読み取り状態で絞り込めます。

前回保存したデータだけを見る場合は、**`ViewLibrary.cmd`** をダブルクリックしてください。曲ファイルの再スキャンは行いません。この起動手段では既定の SONG パスを使用します。別のパスには下記のコマンドを使えます。

曲ライブラリと GUI には Python 3.10 以上が必要です。ローカル環境には Python 3.11.5 と tkinter があり、追加パッケージは不要です。OCR には別途、検証済みの Python 3.11 の独立環境を使用します。これは Python ツールと起動ファイルの構成で、まだ EXE 化されていません。GUI はローカルのブラウザーで表示します。リアルタイム監視、リザルト OCR、手動確認は組み込み済みですが、正式な成績の書き込みとランプ操作は未実装です。

## データソース

| 項目 | 取得方法 |
|---|---|
| 曲名 | SM／DWI の TITLE、SM の SUBTITLE は元のタイトルとともに保持します。osu は TitleUnicode／Title を使用します |
| Artist | 各ソースの ARTIST／ArtistUnicode／Artist を保存し、異なるソースの作者は統合しません |
| Pack／フォルダー | SONG のディレクトリ構造を使用します。connect は管理用 Pack で、pack_type=multiplayer_download とし、検証済みの元の Pack としては扱いません |
| EASY／NORMAL／HARD | 固定のゲーム分類です。実際に存在するかはユーザーが確認し、後から画面の証拠と連携できます |
| ゲーム内 LV | 公式曲は確認済み CSV のゲーム内数値を使用します。自作曲は手動入力し、後から本人の画面から取得します。SM／DWI／osu の難易度数値は読み取りません |
| 完全な総ノーツ数 | 公式 CSV または手動入力のゲーム内数値を使用し、後から本人の画面からも取得できます。HOST 以外は、確認済みのルールに従い、正常終了後の判定合計から算出できます |

各 SongFolder は独立した曲で、ルートディレクトリと Pack／SongFolder の相対パスで識別します。同名、同じ Artist、同じ BPM であっても、フォルダーをまたいで統合しません。SM＋DWI は通常のソース情報として保持し、それを理由に曲を分割しません。特殊な SM＋DWI＋osu フォルダーは手動確認の対象とし、優先する形式を選びません。ファイル内の Challenge、SMANIAC、osu Version などはゲームの難易度項目に入れません。

ソースの曲名が一致しない場合は候補を保持し、自動で決定しません。Pack やフォルダーが異なる同名曲も自動統合しません。曲名がない場合は不明のままとし、フォルダー名や難易度名で補完しません。ファイルの SHA-256 はソース／読み取り専用の照合にだけ使い、ゲームの Chart ID ではありません。

## コマンドライン

```powershell
python -m dance_results --root 'D:\Dance v1.9.0-dev-be622\DATA\ADDON\SONG'
```

指定したサンプルだけをスキャンする場合：

```powershell
python -m dance_results --folder "Blue's 1st step\eos[Blue]" --folder 'osu音樂\Gotta Get Thru This (Jauz RetroFuture Remix) (Nightcore [2b5a993e]'
```

| オプション | 用途 |
|---|---|
| `--choose-directory` | SONG フォルダーの選択画面を開きます |
| `--folder` | SONG 内の指定フォルダーだけをスキャンします。繰り返し指定できます |
| `--output` | レポートの親ディレクトリを指定します。SONG 内には指定できません |
| `--open-report` | 完了後にレポートを開こうとします |
| `--legacy-encoding cp950` | UTF-8 で失敗した場合、明示的に指定された文字コードでデコードします。文字を自動推測しません |
| `--database` | SQLite ファイルを指定します。既定値は `data/library.sqlite3` です。SONG 内には置けません |
| `--library-only` | 保存済みデータだけを読み取って一覧を生成します。スキャンは行わず、`--folder` と併用できません |

保存済みの曲ライブラリを直接開く場合：

```powershell
python -m dance_results --library-only --open-report
```

このバージョンではノーツを解析しないため、旧版の `--include-events` は削除しました。

レポートは毎回 `reports／時間戳記／`（タイムスタンプ） に新規作成し、HTML と JSON を含みます。元の曲ファイルは読み取り専用で、レポートを SONG に書き込むことはありません。Ctrl+C で正常に中断した場合は途中の結果を保持しますが、強制終了した場合はレポートが作成されないことがあります。

## データベースと再スキャン

- 同じ SONG ルートディレクトリと曲フォルダーには同じ曲 ID を保持します。再スキャンしても同じパスを重複追加しません。
- スキャンのたびにスナップショットと診断情報を保存し、ソースファイルにはそれぞれ ID を付けます。前回完全に読み取れた曲名と今回の結果は別々に保存します。今回の失敗／競合で保存済み曲名を上書きせず、古い曲名を今回確認できた結果として扱うこともありません。
- 完全スキャンで見つからなかったソースは未検出として記録し、曲、ソース、ゲーム譜面の関連付けは削除しません。同じパスが再び現れた場合は元の ID を復元します。
- `--folder` は指定範囲だけを更新します。中断、ディレクトリの読み取りエラー、リンクのスキップがあった場合、読み取れなかったソースを消失したとは扱いません。
- 改名／別の曲フォルダーへの移動があった場合、現時点では自動統合しません。新しい場所に新規項目を作り、古い場所は確認待ちとして保持します。同じファイルハッシュだけでは、同じゲーム譜面であることを証明できません。
- `charts` は安全に `game_difficulties` へ改名し、EASY／NORMAL／HARD だけを許可します。一部の難易度だけが存在することもあります。ユーザーが存在を確認してから作成し、未確認のものは自動作成しません。LV、総数が未設定の場合は NULL です。
- `play_sessions`／`play_records` には、マルチプレイの HOST、本人の難易度と HOST LV の分離、本人が失敗してリザルトを待つ状態、ソース不明で手動の対応付けを待つ状態に備えた構造を用意しています。対応付けが未完了または未検証のものは最高 EX とベストランプの対象にしません。この段階ではデータ構造とクエリだけを作成しており、成績の取得／入力機能はありません。
- 元の Title とゲーム表示の曲名は `song_title_aliases` を使って別々に保存し、表示曲名を一意識別子としては使いません。
- `ViewLibrary.cmd` に表示されるのは保存済みデータで、異なるスキャン時点のデータが含まれることがあります。未検出のソースは明示します。現在の状態を再確認済みという意味ではありません。
- schema 2→3 では connect Pack とソースの saved_artist を追加します。先に SQLite backup API でバックアップと監査を行い、トランザクション内で移行し、失敗した場合はロールバックします。schema 1 は順にアップグレードできます。互換性のないデータベースは上書きしません。

この段階では曲ライブラリの GUI とゲーム難易度の手動編集を提供しています。OCR、成績の入力／取得、HOST 以外の成績の手動対応付けは組み込んでいません。テーブル、難易度別のベスト記録のクエリ、マルチプレイの境界条件については [docs/DATABASE.md](docs/DATABASE.md)をご覧ください。

## スキャンの範囲と制限

- `SONG／Pack／Song` の階層に沿ってスキャンします。曲フォルダー内の FileBackup などのサブディレクトリには再帰的に入らず、通知を表示します。
- 曲名は `.sm`、`.dwi`、`.osu` からのみ読み取ります。`.old`、`.osb`、`.dps`、`sdoinfo.dat` は別途一覧に示し、曲／譜面のソースとしては扱いません。
- UTF-8／UTF-8 BOM、UTF-16 BOM はそのまま読み取れます。他の項目の文字コードが原因でファイル全体の読み取りに失敗した場合は、項目ごとに名前を厳密に読み取り、完全なエラーと元の bytes を保持します。CP932／Big5／CP950 は明示的な指定がある場合だけ使用します。複数の解釈がある場合や文字化けが疑われる場合は手動確認待ちとし、自動で候補を選んで上書きしません。`--folder` で範囲を絞ることをおすすめします。
- 1 ファイルの上限は 64 MiB です。読み取り中にファイルサイズ／更新日時が変わった場合は、再スキャンを待ちます。ディレクトリ／ファイルのリンクと Windows reparse point はたどりません。
- 旧版の HTML レポートはオフラインで動作します。GUI はローカル HTTP API 経由で SQLite にアクセスします。ソースのテキストは textContent で表示し、外部ネットワークリソースは使用しません。
